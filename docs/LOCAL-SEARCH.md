# 로컬 기록 검색

2026-11-05 구현·검증 기록. 대상은 제목·대화록·요약 검색과 근거 발언 이동이다.

## 문서 기준과 근거

- 검색과 저장 문서 화면은 같은 읽기 전용 스냅샷을 사용한다.
- `transcript.md`가 JSON에서 생성한 문서와 같거나 파일이 없으면 확정 세그먼트를 표시한다. 검색 위치에 겹치는 원래 세그먼트의 시작 시각을 사용한다. 표시 문단의 시작 시각과 검색한 발언의 시작 시각은 다를 수 있다.
- 외부에서 수정한 `transcript.md`는 수정한 원문으로 검색·표시한다. 시각이나 화자 대응을 추측하지 않는다. 요약의 시각 문자열도 재생 근거로 해석하지 않는다.
- 결과는 회의 UUID, 문서 바이트·메타데이터 해시, 블록 식별자, 원문 UTF-16 범위를 가진다. 클릭·재생 직전 원문과 회의 경로·ID를 다시 검증한다.
- 원본을 쓰는 기존 마이그레이션 로더를 검색에서 호출하지 않는다. 파일 누락·손상·권한 실패·중복 ID는 경고하거나 결과를 제거한다. 심볼릭 링크와 저장 폴더 밖 문서는 읽지 않는다.

## 검색과 갱신

NFC 정규화와 영문 대소문자·악센트·문자 폭 접기를 적용하고 공백을 무시한다. 숫자의 쉼표·소수점과 다른 구두점은 구분한다. 문단 내 연속 구절 검색이며 의미 검색이나 여러 단어의 AND 검색은 아니다. UI 검색어는 최대 256자다.

파일 읽기·정규화·매칭은 별도 actor에서 수행한다. 캐시는 메모리에만 있으며 앱 재시작이나 저장 폴더 전환 후 재생성한다. 스냅샷 캐시는 추정 128MiB, 정규화 캐시는 추정 96MiB를 상한으로 관리한다. 캐시 추정치는 전체 프로세스 메모리 상한이 아니다.

실제 파일 바이트를 다시 읽어 변경을 확인하므로 같은 크기·inode·수정 시각으로 바뀐 문서도 탐지한다. 선택 문서는 약 3초마다 확인한다. 검색 결과는 작은 보관함에서 약 3초, 200개 초과 보관함에서는 약 10~12초 간격으로 갱신한다. 수동 새로 고침과 새 검색은 즉시 요청한다. 취소 후에는 자동 재시작하지 않는다.

전체 일치 수를 계산하고 처음 200곳을 표시한다. 메타데이터는 파일당 32MiB, 대화록·요약은 각각 16MiB까지 읽는다. 한도를 넘는 파일은 경고하고 해당 문서를 생략한다. 파일을 읽는 도중 교체·수정되어 검증에 실패한 경우 다음 갱신에서 재시도한다.

## 검증

최종 `bash scripts/build-app.sh` 빌드, `RecorderChecks` 65/65, 설치 검사 10/10, 앱의 strict/deep 서명 검증을 통과했다. 서명 방식·인증서·녹음 권한을 변경하지 않았다.

자동 검사 범위:

- 한국어 부분어·띄어쓰기, NFD·이모지·전각 영문·악센트, 숫자·구두점과 원래 UTF-16 강조 범위
- 같은 구절이 있는 여러 회의, 합쳐진 문단 뒤쪽 세그먼트의 실제 시각
- 외부 Markdown·요약 갱신, 같은 inode·크기·mtime의 변경, 오래된 결과 거부
- 4,000자 경계에 걸친 긴 문단 검색, 원문 줄바꿈·문자 보존
- 회의 이동·삭제·중복 ID, symlink·손상·읽기 권한, 오디오 누락·권한 변경
- 검색 취소·초기화·재시작 후 메타데이터·Markdown·오디오 바이트 보존

실제 앱 화면에서 합성 기록으로 확인한 범위:

- `출시일정`으로 서로 다른 두 회의를 찾고, 결과 선택·강조 및 실제 12초 지점 재생
- 요약 검색과 문서 이동, 외부 수정 대화록 표시·재검색, 근거 없는 재생 버튼 미표시
- 500개 기록 색인 중 무음 테스트 음원의 재생 위치 지속
- 마이크를 끄고 합성 음원 앱만 약 25초 녹음하면서 1,000개 기록 검색, M4A 저장 완료
- Escape 취소, 자동 재시작 방지, 다시 검색, 결과 없음, 검색 범위 선택

합성 기록과 검증 녹음은 `.build` 아래에만 생성했다. 검증 후 사용자의 저장 폴더·전사 모델·마이크·녹음 대상을 복원하고 기존 기록 13개가 표시되는 것을 확인했다.

## 성능 측정

Apple M2 / Mac14,2 / RAM 16GiB / macOS 26.5. 익명 합성 회의 1,000개, 발언 100,000개, JSON·Markdown 합계 60,753,780바이트. 기록마다 파일을 다시 읽는 전 과정을 포함한다. 모델은 다운로드하거나 실행하지 않았다.

| 측정 | 최종 실행 |
| --- | ---: |
| 첫 색인 + 검색 | 14.81초 |
| 반복 검색 10종 중앙값 | 1.25초 |
| 반복 검색 최대 | 1.41초 |
| 결과 원문 재검증 | 0.26초 |
| 선택 문서 로딩 | 0.14초 |
| 검사 프로세스 최대 RSS | 274.6MiB |

이 값은 합성 데이터 1회 측정이며 실행 환경·실제 문서·다른 작업에 따라 달라진다. 앱 전체가 음성인식 모델과 함께 사용하는 메모리 수치는 아니다. 최초 색인의 지연이 남아 있으며 더 큰 보관함에서는 디스크 기반 색인 도입을 별도로 평가할 수 있다.

재현:

```sh
bash scripts/build-app.sh
.build/release/RecorderChecks --search-only
.build/release/RecorderChecks --search-benchmark
```
